# Division migration: census, source review, and execution

The repository census is complete. Source migration remains open wherever the
actual application compiler or runtime cannot yet preserve the required source
and build contract. This report distinguishes the collected source snapshot,
published changes, and executable evidence. A zero slash count is not a fleet
acceptance result.

## Source inspection

`c-source-producers-public.tsv` records 229 source instances from 28 focused
default/PR profiles. Their 190 distinct C/header blobs were read and verified
against Git object identity before scanning. The ledger names the declaration
that actually selects a compiler, including mixed ICK/NDK or ICK/stock-C routes.
Its counts describe the observed blobs, before subsequent published changes.

The new scanner is the actual Idriç program
[`AuditC.idric`](../../../examples/autogenerated/division-glyph-migration/AuditC.idric).
It handles C line splicing before token recognition and retains physical source
locations. It distinguishes binary division, compound assignment, preprocessor
tokens, strings/comments, malformed quoted regions, and trigraph review. Lua
long-bracket literals/comments and floor division have their own lexer. Idriç
nested comments, primed identifiers, multiline strings, and inequality also have
separate handling; interpolation is reported for manual review. The scanner
accepts explicit C, header, Lua, and Idriç filenames. Its compiled self-tests
pass; missing arguments, unreadable files, and unsupported extensions fail.
It never rewrites source, guesses ownership from a directory name, or grants
compiler qualification. The initial Python implementation and its tests were
removed after their lexical controls were ported to Idriç, preserving the
repository's existing prohibition on new first-party Python. Repeating the
190-blob C scan with the extended Idriç scanner produced identical findings.

All 701 default/PR `.idric` path instances were classified after reading all
292 distinct blobs, with no fetch failures. The public classification table
contains 699 of those instances. Slash characters in path/URL literals and the
distinct `/=` inequality operator are preserved. Generated C strings are
classified at their generator and actual downstream C compiler boundaries.

Owned Icky Lua consumer files in Young Tableaux, Toki Pona, and FastChat contain
no remaining binary ASCII division; the actual Icky Lua module/tests were run.
The two divisions in `place-of-honor/game` are attached to its stock LÖVE runtime
and cannot be accepted merely by running a different Lua executable.

## Remaining acceptance boundaries

Android NDK r27c CMake enables `_FORTIFY_SOURCE=2` even when a project does not
spell the flag in its own CMake file. Its fortified headers use Clang overload
and object-size features that the current ICK frontend does not implement.
An ordinary Bionic-header compile without that flag does not qualify an
application that previously required it. The migration must preserve those
checks or provide an independently qualified, bounded equivalent; removing
hardening to obtain a green build is not accepted.

The remaining C ledger also distinguishes frozen numerical comparison controls,
kernel/upstream substrate, pseudocode and broken copied snippets, generated C,
and executable owned source. A source file with no arithmetic division needs no
spelling edit. Existing build failures and runtime boundaries do not become
successes because a file was inventoried.

Binary `÷` retains the operand types, truncation/rounding, precedence, and order
of `/`. C compound division needs semantic review of its lvalue; duplicated
side effects are not acceptable. Lua `//` remains floor division. C preprocessor
evaluation is a separate qualification from a macro expanded into ordinary C.
Unchanged upstream and `.idr` compatibility source are preserved.

No compilation, native test, or newly built APK is physical phone/tablet
acceptance. Existing device and release gates remain distinct from this source
migration, and no new consumer PR is merged by this report.
