# Large streams and memory

`stream.c emit single|many BYTE_COUNT` creates deterministic mailbox-shaped data
without retaining it. `single` starts one envelope/header block followed by long
body content. `many` repeats a small record. A count may cut the final record;
the source recipe and count, not a guessed parser outcome, define exact bytes.

`check ABSOLUTE_ADAPTER ARG single|many BYTES MEMORY_MIB RECEIPT` runs a child
with a Linux address-space limit, writes bytes incrementally, and compares its
reported count and SHA-256 with the controller's calculation. Candidate stdout
must be one count/hash TSV row. The adapter must feed its real streaming path;
build/process witnesses must establish that fact. The built-in `probe-stream`
only hashes bytes. `probe-buffer` intentionally retains the entire source;
`probe-offset32` intentionally truncates the final count. These test the gate,
not any mail implementation.

Run single-message and many-message cases at small, medium, and >4 GiB sizes.
Record total generated bytes, measured peak RSS, address-space cap, exact binary,
OS/ABI, time limit, and outcome. A base-offset-only test exercises arithmetic but
does not substitute for processing >4 GiB. This branch exercises both kinds.

Choose per-language budgets before a run, allowing a fixed runtime baseline.
Require approximately bounded growth as total mailbox size increases, not equal
allocation totals across languages. Heap/RSS caps, CPU deadlines, scratch-disk
quota, and output caps are different limits. Current small-runner file caps do
not apply to the large raw-stream probe. A production parser should stream or
spool a huge single message rather than materialize it; any intentional maximum
must fail explicitly, retaining source/restart evidence.

Remaining acceptance: measure the actual parser and its children; require
observable early consumption, backpressure, cancellation, and bounded scratch
storage as appropriate. A process can hash input in bounded memory while a
different process buffers it; the probe's cooperative one-child RSS evidence
does not close that loophole. The real adapter must not replace parsing with a
digest-only path.
