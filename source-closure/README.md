# Independent source-checkout admission

This is the source-acquisition slice of BC-P02-S04 under [ai-ci issue 149](https://github.com/isomorphisms/ai-ci/issues/149). It consumes BC-P02-S01's `catfood-source-v1` output. Existing [package closure](../package-closure/README.md) remains responsible for delivered archives; source admission does not replace package execution or compiler witnessing.

The verifier is [SourceAdmission.idric](../examples/autogenerated/source-admission/SourceAdmission.idric), compiled through the exact Idriç host compiler. Its command interface is:

`source-admission EXPECTATION.tsv CHECKOUT EVIDENCE.tsv`

The independent caller supplies a trusted `aici-source-expectation-v1` TSV with exactly one `schema`, `repository`, `commit`, `submodules` and `role` row. `role` is `ordinary` or `ick`; `submodules` is `none`, `skip` or `recursive`. Repeated `origin` rows may name explicitly approved former repository addresses. These expectations must be pinned separately from the candidate record. The checked-in ICK workbench/producer contracts pin the actual source revision and permit its verified former origin. `skip` checks declarations without admitting child bytes or deleting a previously populated reference. The separate fresh-acquisition replay checks that ordinary ICK did not populate GCC.

The verifier reads committed Git trees, index entries and the actual checkout independently. It rejects wrong origins/HEAD, hidden index or sparse state, missing/extra source, raw bytes hidden by Git normalization, modes and symlink payload changes, intermediate symlink escapes, declaration/gitlink mismatches, missing or incorrect required descendants, and ICK lock/material disagreements. Git status is deliberately not used: it can normalize bytes and invoke local clean filters. Immutable Git blobs supply material expectations; raw working bytes must match those blobs. The complete independently reconstructed sorted record and SHA-256 must equal the candidate bytes, so rehashing false rows cannot make them acceptable.

The supported observer host profile is Debian/Ubuntu Linux with standard GNU tools. Git runs with a cleared Git environment, optional index writes disabled and a fixed provisioned-host search path; utility paths are explicit. The checker performs no fetch, checkout, submodule update, source repair, download, installation or build. Source and Git metadata immutability are checked around each independent fixture invocation. This is an observer, not a sandbox against a hostile concurrent administrator or replacement of its trusted runtime.

`SourceAdmissionFixtures.idric` constructs real Git fixtures and expected records independently of Cat Food. Its negative candidates include internally valid, rehashed false evidence. It imports process primitives only, not the producer or admission logic. `SourceAcquisitionReplay.idric` separates actual Cat Food acquisition from the read-only checker and retains both exits, candidate TSV and verifier result. The replay program may acquire source; the verifier cannot.

The focused workflow pins both Idriç and Cat Food source, builds Idriç through its maintained ICK-qualified Chez bootstrap, compiles the actual `.idric` verifier and fixtures, runs the independent corpus, then acquires actual pinned ICK workbench and producer source before independent verification. Every stage records its own result. Generated artifacts remain under the existing build directory and are not maintained source.

A `PASS SOURCE-CHECKOUT` covers only that repository/commit, reference policy and hosted source material. It does not authenticate BC-P01 process witnesses, approve FP authority, qualify archive behavior or an eligible managed Grease closure, publish a package, or establish Android/physical-device acceptance. The original format-only shell prototype remains a partial historical artifact; it is not reused as source admission.
