# Independent transfer observation controls

`check.pi ROOT ITHON OUTPUT` executes the checked maintained validator against
four passing semantic specimens and twenty-one targeted broken specimens.
These are oracle fixtures, not a substitute for executing Kitchen's generated
script or a transfer against GitHub. The full producer qualification separately
executes the thirteen Kitchen API scenarios against the exact recipe bytes.

The supervisor supplies the trusted configuration and records API observations
outside the candidate UID. Successful HTTP responses and their bodies must
establish authentication, login, source identity/capability, destination identity
and permission, collision absence, the precise transfer effect, and independent
numeric/canonical destination observations. Methods other than GET and the one
authorized transfer POST are rejected. Summary fields cannot overrule recorded
responses.

`execution.json` now includes `runs`, each with `exit`, `event_begin`, and
`event_end`. The trusted controller snapshots event counts immediately before
and after each child. Ranges must cover the observations contiguously; the first
invocation performs the only transfer attempt, and the next invocation reconciles
without resending. A no-op first invocation cannot inherit a later invocation's
postcondition. Older aggregate observations without these bounds are historical
evidence, not current acceptance.

The controls also prove failed repeated validation replaces a deliberately stale
PASS receipt, and an always-refuse implementation fails a supported positive
request. The recorded test scope excludes deployment, real transfer, and fresh
model judgment.
