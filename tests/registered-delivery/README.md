# Independent registered delivery fixtures

`check.pi OUTPUT_DIRECTORY` imports the checked owner modules through the Ithon
runtime. Its import path must include this repository's `validators/` directory
and the selected Flexible Pipes `scripts/` directory. The output directory must
be new. The harness itself must run through the Ithon frontend.

These cases test the registered acceptance oracle, using private fixture files
for the supplied authority configuration, recipe/checker identities, contract,
qualification, and runtime bytes. Recorded repository commits and publication
references are explicitly synthetic: this suite does not check Git publication
or ancestry, install a trusted controller, execute Kitchen recipes, or exercise
a real ChatGPT response adapter. Those claims require the owning route's
separate execution and admission evidence.

The positive fixture has the maintained contract's two output roles and all
twenty-four required checks. It composes and renders through Flexible Pipes' owner
module, then independently constructs the captured visible event. It never
calls the producer's delivery method to fabricate that observation. Fixed input
acceptance is tested twice; an oracle that always refuses fails the positive
controls.

Negative cases change source and checker bytes under the same recorded commit,
remove runtime/source files, mismatch request identities and parameters,
replace qualification/release/control evidence, skip a check, remove a check
together with its declaration, invent promotion evidence, alter or omit outputs,
rewrite/truncate/substitute the captured response, and provide a blocked result
instead of the requested generation. Each rejection requires its named
diagnostic, preserving failure-class evidence rather than treating every
exception as success.

The CLI control first accepts a complete captured delivery, then uses the same
receipt path for a link-only response and a malformed request. Both repeats must
replace the prior PASS with FAIL. The suite publishes its own final PASS only
after these receipt controls complete.

The removed-check/declaration mutant edits the authority contract while retaining
its protected configuration, material, contract, and qualification digests. A
proposal cannot approve those changed authority bytes. The existing owner gate
separately checks the mandatory check list; this oracle does not duplicate that
registry. Branch request positives and mutants bind commit, request path, Git
blob identity, and request digest to the independently supplied submission.

The generated fixture snippets visibly name the transfer POST but are identity
test data, never executed or served as maintained transfer commands. Successful
fixture acceptance is not transfer execution or deployment acceptance.
