# Installed protected-admin observation

This independent observer drives the installed native IB application and its
protected WebView. The simulated remote application lives in IB at
`examples/autogenerated/admin-longview-fixture`; it is built through the
qualified ICK executable supplied by the caller. Its only network address is
the emulator loopback forward `http://127.0.0.1:18493/`.

## Entry points

All path arguments are absolute; the caller's current directory is irrelevant.

Set `IB_GREASE` to the qualified Grease executable. The installed coordinator
also requires `AICI_EXPECTED_ANDROID_API=29` or `34` and
`AICI_ADMIN_PUBLIC_LADDER=0` or `1`. The public ladder is selected only for the
separate API 34, one CPU, 1 GiB emulator. Guest CPU count, guest memory and the
480×800 viewport are observed. Normal lanes require two online CPUs and memory
compatible with the declared 2 GiB guest; ranges allow kernel reservations.
Requested and measured capacity are retained before the mismatch assertions,
so a rejected guest still leaves its actual CPU and memory evidence.

## Actual deterministic path

The observer opens the real native Open/Resume controls. Within the page, it
finds rendered control bounds and injects platform pointer down/up events.
It never substitutes JavaScript `.click()` or a ready marker for the usable
action. The HTTP server independently counts that action. The negative page
must itself be loaded with its known title, origin, path and disabled control
before the same action assertion is required to reject it.

The main path observes the control's server confirmation, follows the mock
verification detour, observes Activity pause and resume during an app switch,
and obtains one synthetic terminal result. The result stays inside the target
process: its shape predicate returns only a Boolean, and the observer erases
the result and observes its absence before taking any screenshot.

The real native timing callback also receives the actual synthetic result in
an otherwise numeric array. A captured current record and boxed document epoch
bind it to the real WebView. Acceptance requires its fixed numeric rejection
event. A positive numeric callback on the initial document proves the parser
path was reached while attribution is valid. Saved
callbacks are submitted after a same-WebView document replacement and after
actual renderer termination; both submissions must complete without emitting
stale timings. There is no production test-ready flag or test callback.

After the same-WebView navigation, a single observer UI-thread operation calls
the actual product client's visible-commit and finished methods with the old
verification URL, then with the repeated current root URL. Its independent
`IBAdminProbe` tag contains only fixed numeric begin/end markers and the actual
host PID. Between those markers the closed verifier requires exactly four
UNKNOWN results (`code=2`, `document_epoch=0`, `elapsed_ms=-1`), in call order
and under unchanged host, Activity and renderer generations. Every checkpoint,
accepted lifecycle callback or timing measurement inside the interval fails.
Canonical task snapshots must also remain byte-identical. Byte equality alone
does not establish that no checkpoint was attempted; the bounded event check
supplies that assertion. Real initial-document and replacement-renderer commit
and finish events remain required positive controls.

The fixture commits an ambiguous operation and closes a truncated response.
The observer sees the uncertainty, writes and observes unapproved form input,
and terminates the actual renderer. It then recreates the Activity, force-stops
the host, and performs replacement installation. Task, tab and navigation
identities must persist; only the applicable generations advance. The remote
mutation and one-time delivery counts stay exactly one. Form recovery remains
`repeat-required`, authentication remains `not-proven`, and the lost heap is
not claimed as recovered.

Snapshots validate the complete selector and both selected identities against
the task record. The real snapshot path executes positive and known-bad selector
controls without altering the live store. Host-side receipt validation rejects
unknown or duplicated fields, impossible Int32 generations, wrong identities,
stale lifetimes, false authentication/heap/form claims and repeated operations.

## Evidence and privacy

Screenshots are captured inside the live observer before the result appears
and after reconstruction. The receipt binds IB and observer source, candidate
and installed APK digests, package/version, persistent signer, API/ABI and
WebView implementation. Screenshots are not deferred until Instrumentation
has terminated the target process.

Only the fixed `IBLongView` tag and observer-owned `IBAdminProbe` boundaries are
collected. Their closed contracts admit only declared numeric keys, including
`host_pid` and `document_epoch`. The marker payload is never product evidence
of readiness or success. Unsafe raw
diagnostics and unvalidated task snapshots are withheld. No cookie, response
body, URL query or terminal value belongs in an ordinary receipt.

First useful control and first confirmed action have separate elapsed times.
A bounded sampler records host PSS and `USER PID PPID NAME`, with no process
arguments. Its maximum is the maximum of those samples, not an unobserved peak.
The association between an OS renderer PID and an opaque durable renderer ID
is `UNKNOWN`. App data size includes test snapshots and screenshots. The
server's parent-byte counter excludes delayed child responses and is not total
network transfer.

### Private records under the actual target UID

The candidate remains non-debuggable. The observer uses the existing
same-signature Android instrumentation boundary and checks that its actual
process UID equals the target package's application UID. It also checks the
fixed target package and the absence of `FLAG_DEBUGGABLE`. The coordinator
still verifies the established signer and compares installed APK bytes with
the candidate before observation. The reader observer's separate `app_process`
execution runs under the shell UID and cannot establish this private-data
boundary.

A preflight phase runs before any Activity launch. Only an actual
`NoSuchFileException` for the selected-task path establishes absence; access
errors and an existing selector fail. After the negative page creates a task,
the same preflight must refuse that existing namespace. Neither preflight
launches the Activity. Storage measurements use `StorageStatsManager` for the
observer's verified own UID: `data_bytes` already includes cache, while
`cache_bytes` is reported separately and is not added again. These are storage
statistics, not the old `du` allocated-KiB measurement.

Snapshots and screenshots are exported during their original instrumentation
phase, before that process ends. No extra instrumentation invocation is used
to pull private files or mutate retained task state. The transport accepts
only fixed per-phase names, bounded byte and chunk counts, contiguous parts,
status-code pairs, exact SHA-256 digests and canonical base64. The host checks
the actual target UID and non-debuggable flag in every completed phase.
Canonical task selection remains checked inside the target process; the
independent host oracle still validates the exported task semantics and its
known-bad mutations.

Raw encoded transport is captured in a private staging path. It is not an
ordinary transcript. Failed decoding removes payloads; the transcript's
protected-value check runs even when chunks are malformed or missing, and an
unsafe transcript is deleted before anything is printed or retained. The
fixed PNG in `fixtures/` exercises multi-chunk transport only. It is not a
screenshot or product acceptance evidence.

## Separate public-page ladder

After deterministic retention assertions pass, the optional public ladder runs
these fixed pages, each with a 180-second outer bound:

1. `https://duckduckgo.com/?q=Michigan+unemployment+insurance&ia=web`
2. `https://miwam.unemployment.state.mi.us/ClmMiWAM/_/`

It supplies no credentials and performs no login/logout action. DuckDuckGo
requires a visible enabled result anchor. MiWAM requires its named public page
and a visible enabled login/claimant entry control; a branded error page with
a generic home link is insufficient. Both require an observed host PID, page
start, visible commit, finish, numeric navigation timing, a source-bound
screenshot and no main-frame error. Failures receive separate
`BLOCKED_NETWORK`, `BLOCKED_SITE` or `UNKNOWN` results. An incomplete ladder
makes that lane nonzero while retaining the deterministic fixture result.
Changed public selectors require review; an unfamiliar page does not pass.

## Qualification boundary

`host-qualification/` retains exact source digests and Linux x86_64 results:
oracle positives, 31 targeted record rejections, 23 diagnostic rejections,
22 transport rejections, DEX assembly/disassembly, resource packaging and
persistent-signature checks.
These are host results only.
The initial published observer's receipts remain under
`host-qualification/initial-40ff487/`; they describe that earlier source.
The lifecycle revision remains under `host-qualification/lifecycle-81b9fe7/`.
The current receipt and source digests bind the actual-target-UID transport
repair. The exact hosted API 29 private-access failure is retained separately
in `host-qualification/installed-api29-before.tsv`; its successful installation
does not become a successful admin runtime observation.

The test-only instrumentation DEX is separate from the candidate and uses
existing Android platform/test interfaces. It never replaces IB's checked
Idriç Activity or native adapter. No Java app source, Gradle app build,
uninstall or app-data clearing is introduced.

Installed Android remains `NOT_RUN` until these assertions execute against
the exact candidate. Live Google Cloud/YouTube authorization, real one-time
credentials, general approved-form recovery, external OAuth return, Shizuku
death, reboot and physical C67 acceptance remain separate pending work.
A build, install or deterministic fixture does not establish those outcomes.
