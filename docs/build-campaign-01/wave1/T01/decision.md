## Compatibility and receipt contract

Ike's verified command is `ike [target]`, with at most one target argument, reading `Ikefile` in its working directory. The default target is the first declared rule. Literal `TARGET depends on DEPENDENCIES`, indented recipe lines, file prerequisites and left-to-right at-most-once dependency traversal are supported. Variables, pattern rules, implicit rules, arbitrary GNU Make flags and Makefile parsing are not supported. `-j`, `-f`, `-C`, variable assignment arguments and multi-target requests must produce typed compatibility blockers before recipe execution unless a separately qualified conversion explicitly covers their semantics. Do not quietly discard them.

`IKE_RECIPE_RUNNER` selects an absolute executable with the existing temporary-source-file protocol; failure is fatal. Absence selects the existing POSIX `system()` boundary. The inspected leaf intentionally qualifies that exact POSIX interface and rejects alternate runners. This does not authorize new Grease procedures to fall back to POSIX, or relabel a C++ Oils binary as an eligible managed Grease runtime.

The receipt records caller-supplied Ikefile identity, selected target, runner mode/identity, ordered actual rule/recipe events and statuses, then PASS/FAIL. It does not authenticate its own producer or bind every source/runtime material. FP's trusted attempt and ai-ci's independent verifier must bind those outer facts. Ike's mtime no-op is legitimate engine behavior, but cannot satisfy an operation requiring fresh recipe execution. A future-dated `test` file at `2038-01-01T00:00` can skip a recipe while Ike returns PASS; current leaf `qualification/test-compiler-policy.sh` creates that mutant and its checked wrapper rejects the missing recipe. Do not change Ike to always rebuild merely to hide this boundary. Qualified reuse is a distinct BC-P03 contract with material and output validation.
