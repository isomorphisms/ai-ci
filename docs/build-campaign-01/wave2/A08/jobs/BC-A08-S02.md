# BC-A08-S02 — Bind completion to the full operation object set and independent postconditions

1. **Identity and execution:** SUN, Ultra; owner isomorphisms/ai-ci; parent BC-A08 under [BUILD-CAMPAIGN-01](https://github.com/isomorphisms/ai-ci/issues/239); canonical [issue 245](https://github.com/isomorphisms/ai-ci/issues/245), with delivery evidence in [issue 219](https://github.com/isomorphisms/ai-ci/issues/219).

2. **Outcome:** A maintained multi-object operation cannot be called complete from selected objects, delivered instructions, producer-written PASS or a narrower evidence class. Every required object must have a fresh independent result bound to the admitted operation.

3. **Recovered intent:** Issue 245 requires explicit immutable object set, mode, execution result and independently checked final postcondition. The [ten-repository historical record](https://github.com/isomorphisms/ai-ci/issues/219#issuecomment-6093384645) establishes real scoped success, not generic proof for subsequent jobs.

4. **Current evidence:** [isomorphisms/ai-ci PR #264, “Independently check native transfer effects and block forged promotion”](https://github.com/isomorphisms/ai-ci/pull/264) is merged at main 949a60dad5e014cafce2c49619df9bbdbcfaafc0. `transfer-handoff/verify.grease` independently observes one destination ID/upstream and permanently rejects publication; `tests/transfer-handoff.grease` has forged PASS, changed bytes and independently corrupted API controls. This source does not establish arbitrary complete multi-object admission or deployed trusted delivery.

5. **Reuse:** Extend this existing verifier and FP retained operation records. Preserve AICI-HANDOFF-01 for exact human-command/native-runtime coverage. Reuse A06 transition invalidation and S01 completion adapters; do not build another controller or duplicate transfer mutation code.

6. **Scope and ownership:** AICI owns independent object-set coverage and final evidence-class rejection. FP executes the registered operation and retains attempts; Kitchen materializes; Cat Food acquires prerequisites; application owners define their semantic postconditions. Add only the bounded adapter required by the existing transfer workflow, not a universal mutation framework.

7. **Prerequisites:** Source implementation and read-only fixture qualification are READY. Consume immutable admitted operation/object-set bytes from the existing FP contract and separately released A06/S01 interfaces. Each record binds request/mode, source/program/material digests, canonical object identity, attempt and observation time. Changed objects or authority require renewed admission; stale successful observations cannot cover a new attempt.

8. **Work:** Implement set-complete verification and connect its verdict to the existing completion caller. Resolve canonical identities independently; reject omission, duplication, redirection and unexpected additions. Observe every required final object using read-only owner APIs, retaining raw status/body and failed retrieval. Keep source validation, host fixture, delivery, actual external postcondition and physical classes distinct. Consume A04 normalized failures without dropping interrupted attempts. Release a bounded consumer artifact for S01 so a wrong-class or incomplete result cannot close an obligation.

9. **Acceptance:** A complete authorized fixture set and read-only verification of an already-completed scoped operation are positive twins. Reject one omitted member, wrong numeric identity/upstream, stale observation, wrong mode, partial enumeration, forged producer receipt and host evidence relabelled physical. Benign order changes preserve a canonical set digest; semantically changed members alter it. Repeated observation causes zero mutation; retry retains previous failures and never generates a second operation. Include a case where nine of ten objects pass and overall completion still fails.

10. **Evidence limits:** Actual read-only remote observations establish only their exact objects/time. A hosted pass, local payload check or Android byte inspection cannot prove installation, launch or physical behavior.

11. **Completion and continuation:** Deliver the bounded verifier, independent controls, real caller wiring and immutable complete-set evidence or its first named unmet observation. Update issues 245/219 and release the consumer artifact independently of physical acceptance. Return ambiguous object authority to STAR.

12. **Authority:** Read-only verification and isolated implementation are permitted. This new job grants no transfer, dispatch, merge, publication, device mutation or closure authority; existing separately scoped authority must be independently revalidated before any such action.

END OF BC-A08-S02
