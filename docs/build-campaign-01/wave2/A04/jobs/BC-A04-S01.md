# BC-A04-S01 — Normalize stage evidence without erasing failures or inventing causes

1. **Identity and execution:** SUN, Ultra; owner isomorphisms/ai-ci; parent BC-A04 and [BUILD-CAMPAIGN-01](https://github.com/isomorphisms/ai-ci/issues/239); canonical [issue 171](https://github.com/isomorphisms/ai-ci/issues/171).

2. **Outcome:** Existing execution receipts must retain the actual failing stage, actor, exit, selected work and attempt history. A successful wrapper cannot erase failure, and infrastructure failure cannot falsely condemn separately demonstrated application behavior.

3. **Recovered intent:** [Issue 171](https://github.com/isomorphisms/ai-ci/issues/171) separates observation, evidence validity, diagnosis and disposition; its proposed labels are not an implemented universal schema. The shared instructions require scoped actor evidence and distinct build, package, publication and physical claims.

4. **Current evidence:** [AICI 949a60dad5e014cafce2c49619df9bbdbcfaafc0](https://github.com/isomorphisms/ai-ci/tree/949a60dad5e014cafce2c49619df9bbdbcfaafc0) has `contracts/scoped-evidence-v0.contract.tsv`, runtime fixtures, seven-stage `ingestion/`, `merge/state.sh` and the failure ledger, which explicitly does not claim a generic executable classifier. These are partial compatible mechanisms.

5. **Reuse:** Add a narrow lossless verdict adapter over existing owner receipts and corpus, preserving their native fields. Reuse BC-A02-S03's oracle disagreement mapping. Kitchen K05 owns writing complete subprocess/timeout/interruption evidence; FP owns process observation and immutable attempt records.

6. **Scope and ownership:** AICI owns validation and aggregate interpretation. Do not replace owner schemas, shell semantics or process supervision. Unknown cause stays UNKNOWN even when the observed nonzero exit is certain. Preserve optional-stage policy independently from successful required stages.

7. **Prerequisites:** Source implementation is READY after refreshed instructions and exact source reads. Freeze input mappings from existing ingestion, Kitchen K05 and FP receipts as they are released; do not require their whole jobs to finish. Qualified runtime/compiler closure is required for actual tests. Changed receipt schema, stage graph, source, policy or target invalidates old mappings.

8. **Work:** Implement explicit mappings for successful/failed/not-run/skipped/interrupted/timeout observations and malformed/stale/wrong-target/wrong-layer/untrusted evidence. Preserve raw exit/signal, command and source identity, producer/log digests, stage dependency and selected-case completeness. Distinguish an absent receipt from a demonstrated task failure. Compute first required failure while retaining independent completed stages and dependent NOT_RUN stages. Integrate the adapter in one existing verifier/caller rather than expose an unused library.

9. **Acceptance:** Execute correct control, all expected output followed by exit seven, plausible compiler output plus failure, omitted case, timeout, interruption and upload-only failure. Only the true stage/claim is rejected; downstream success cannot repair its history. An unrelated actor crash and successful optional cleanup remain benign. Missing selection or contradictory zero-exit/error evidence blocks acceptance without invented causal diagnosis. Identical observations yield identical verdict bytes apart from declared outer attempt metadata.

10. **Evidence limits:** Lexical workflow scans are source observations; these controls prove only their executed process boundaries. No host receipt establishes Android or physical behavior.

11. **Completion and continuation:** Deliver mappings, actual caller integration, raw controls and independent expected verdicts. Update issue 171 and release exact schema/checker artifacts to K05, A02 and S02. Return irreducibly ambiguous owner semantics to STAR without weakening unrelated checks.

12. **Authority:** Implement/test isolated candidates and prepare draft changes. No merge, closure, release, deployment activation, device mutation or actual dispatch.
