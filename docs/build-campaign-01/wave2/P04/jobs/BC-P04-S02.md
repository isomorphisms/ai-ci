# BC-P04-S02 — Reject finished APK presentation drift through mandatory independent admission

**1. Identity and execution:** SUN, Ultra; owner `isomorphisms/ai-ci`; parent BC-P04 / [BUILD-CAMPAIGN-01](https://github.com/isomorphisms/ai-ci/issues/239); canonical [ai-ci225](https://github.com/isomorphisms/ai-ci/issues/225), composite owner [ai-ci207](https://github.com/isomorphisms/ai-ci/issues/207).

**2. Outcome:** The existing Android gate requires a separately recorded presentation_identity verdict derived from the exact finished APK and independently approved plan. Missing assertions, changed component/icon/localization and candidate-supplied expected values block promotion.

**3. Recovered intent:** Preserve the [reported zero & infinity regression](https://github.com/isomorphisms/ai-ci/issues/225#issuecomment-6060980925), package/signer/version checks and inherited-label semantics. Optional packager checks cannot replace mandatory independent acceptance.

**4. Current evidence:** ai-ci main `949a60dad5e014cafce2c49619df9bbdbcfaafc0`; retained [isomorphisms/ai-ci PR #230, “SUN 1: independently verify Cat Food companion plans and signed APK bytes”](https://github.com/isomorphisms/ai-ci/pull/230), head `0699756155d614bb75caeb679d97e40934b7dced`. Its `android-companion/verify.sh` replays plans and extracts labels, but accepts any nonempty launcher and lacks icon/localization comparison. Composite retained head `5c80279dfcee565f4e999d2b1f97feb966b8efd3` supplies sealed execution/admission to extend.

**5. Reuse:** Continue230, its plan replay and ABI/signer checks, plus NDK's merged resource and staged-publication safeguards. Preserve existing release-promotion implementation; do not duplicate CF07 signer parsing or create another runner. Coordinate A03 for required-assertion authority.

**6. Scope and ownership:** One AICI implementation owns extraction and mandatory comparison together. P04-S01 supplies expected contract, P01/P02 actual qualified tools, CF07 consumes the same artifact/result, FP03 composes. Serialize shared android-companion changes before CF07 integration.

**7. Prerequisites:** Source implementation ready after live-head refresh. Real APK execution requires released P04-S01 plan, A03 approval artifact, pinned admissible extractor/signature tools and P02 closure. Candidate tests can exercise unmerged policy explicitly but cannot issue active acceptance. Missing trusted deployment/runtime remains conditional.

**8. Work:** Extract effective default/app/launcher labels, exact component/aliases, icon resource reference and declared localized entries from final bytes. Reject partial, duplicate or ambiguous extraction. Compare to independent plan; preserve raw extraction and its digest with APK/source/profile/policy/attempt/tool identity. Make the assertion mandatory in existing decision/admission, refusing omission or self-relaxation. Reuse temporary/staged receipt publication and verify digest again at consumption.

**9. Acceptance:** Real resource-bearing good APK passes. Keep native code/package/trusted signer unchanged while changing label, launcher component, icon or required locale; each must fail before publication. Candidate-derived expected fields, stale plan, missing assertion, interrupted extraction and APK swap fail. Declared inherited activity label and harmless resource ordering pass. Repeated exact inputs yield canonical obligations/results, with raw execution/attempt evidence separate. Preserve prior verified output when candidate publication fails.

**10. Evidence limits:** Resource identity is not decoded icon visual quality, device display/launch, update installation or physical behavior. Stub badging qualifies parser plumbing only; actual APK controls are mandatory for package claims.

**11. Completion and continuation:** Deliver actual extraction/admission implementation, positive/hostile/benign APK evidence and exact interface to CF07/P04-S03/FP03; update225/207. Return contradictory approved requirements or unsupported extraction capability to STAR without guessing.

**12. Authority:** Focused implementation and disposable qualification, draft records; no production promotion, key/signer changes, merge, release, installation, closure or activation.
