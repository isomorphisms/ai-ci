# BC-CF01-S01 — Make scoped profiles consumable across maintained Android targets

1. **Identity and execution.** SUN, Ultra; owner isomorphisms/catfood; parent BC-CF01 and [BUILD-CAMPAIGN-01](https://github.com/isomorphisms/ai-ci/issues/239); canonical [Cat Food #110](https://github.com/isomorphisms/catfood/issues/110).

2. **Outcome.** A maintained diagnostic or producer consumer obtains a source-bound profile for A1, C67 or TAB_P10, with required missing/stale observations visible before effects. Stable known facts remain reusable without repeatedly asking the human for a complete hardware dossier.

3. **Recovered intent.** [#118's settled decision](https://github.com/isomorphisms/catfood/issues/118) separates model, instance, firmware, ABI lane, application-context capabilities and acceptance. SurfaceFlinger ES3.2 does not prove an application's GL context. A source profile, service installation and current Shizuku readiness are separate facts. No new registry, speculative targets, ADB setup or tablet SD-card work.

4. **Current evidence.** Main `8ba159f8322cd436aa8e6400b0eded2d74c14011` has separate target detection and narrative A1/C67 profiles but no `android/profile.pi`. That Ithon reader survives on `docs/miro-a1-diagnostic-evidence@a1d36ee45b66a1af86d7594cc18df889610d5c81`, from [isomorphisms/catfood PR #111, “Make the staged MIRO A1 profile and verified Android acquisition consumable”](https://github.com/isomorphisms/catfood/pull/111). It accepts only `miro-a1`, reads `build_fingerprint` while `device-state.sh` emits `fingerprint`, and `--require-current` only requires an inventory binding. These are inspected source gaps, not executed failures here.

5. **Reuse instructions.** Generalize that reader and its source-linked observation/regression files. Reconcile [isomorphisms/catfood PR #136, “FC-M4: classify captured Android identity without planning overrides”](https://github.com/isomorphisms/catfood/pull/136), head `d48e4bd406d6cb5d6cd2fa3f3ea1f78b80277815`: `catfood classify-android-target PRODUCT MODEL PRIMARY_ABI` already exposes the classifier. Its classification is not acquisition or attestation.

6. **Scope and ownership.** Cat Food owns facts, aliases, scoped read/validation and missing-profile outcomes. CF-A2-S2 supplies independently approved material/obligation semantics; S3 supplies installation authorization. Kitchen CF-A2-S5 and retained FP diagnostic execution consume the released interface; coordinate their adapter edits with those owners. Do not duplicate capture, profile constants or producer policy.

7. **Prerequisites.** Source implementation may begin against exact current records. Release the profile schema with S2 before final integration; pin observation bytes, provenance scope, resolver version and required-field policy. Checked Ithon and qualified eligible Grease are required only for their execution lanes. Follow [#131](https://github.com/isomorphisms/catfood/issues/131); no stock-shell or C++ runtime substitution.

8. **Work.** Unify the existing profile/observation shapes, using canonical model identifiers and finite alias resolution. Preserve UNKNOWN, conflicting, missing, historical and branch-only states. Resolve the fingerprint field mismatch explicitly with historical schema handling. Refresh only material mutable facts required by the task; require application-context or session observations when the selected operation needs them. Wire one real S5/FP diagnostic request to this reader before command preparation, retaining its exact profile digest in the request and receipt.

9. **Acceptance.** Execute public profile lookup and that real consumer. Valid unchanged profile and harmless record order pass. Two same-model instances, unknown ARM32/AArch64 hardware, conflicting identity, wrong ABI, absent/empty firmware, stale required observation and SurfaceFlinger/app-context substitution refuse the appropriate stronger claim. A stable GPU lookup needs no fresh phone probe; a stopped service does not erase static facts. Repeat equal pinned material yields equal profile projection; change only a material scoped fact and invalidate the affected request. Prove removing the consumer call is detected.

10. **Evidence limits.** Host captures and supplied properties are not physical acquisition. A1, C67 and TAB_P10 physical receipts remain distinct; new profile coverage does not install provisioning or authorize runtime behavior.

11. **Completion and continuation.** Deliver integrated reader, adapters and independently specified controls, update #110/#118 and the existing scope ledger, and publish exact consumer-interface artifacts. Return only concrete ambiguity about a required fact's scope to STAR; missing deployment blocks its lane, not source completion.

12. **Authority.** Implementation and focused verification only; prepare reviewable owner changes. No merge, closure, device installation/reconfiguration, release, activation, recurring schedule or dispatch.

END OF BC-CF01-S01
