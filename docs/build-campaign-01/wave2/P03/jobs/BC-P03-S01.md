**2. Outcome:** The maintained NativeActivity packager produces the declared stable package bytes from equivalent approved inputs, records exactly what it normalized and preserves verified prior output on failure. Consumers can independently reproduce that boundary.

**3. **4. Its receipt omits the explicit epoch/signature-mode/material identity boundary.

**5. Reuse:** Continue this candidate and `apk/tests/reproducible.grease`; retain old-packager and removed-zip-X mutants. Preserve merged [isomorphisms/android-NDK PR #18, “SUN 1: preserve APK resources and launcher identity in direct NativeActivity packaging”](https://github.com/isomorphisms/android-NDK/pull/18), label/resource controls and staged publication. **7. Prerequisites:** Source-ready after refreshing branch/main and overlapping edits. Actual qualification needs pinned admissible packager/extractor/runtime material and explicit existing test signer. CatFood131 managed non-C++ restriction remains; historical Grease success is not eligibility. Reject material/policy drift and expired required archives.

**8. Work:** Complete receipt inputs for epoch, exact packager/tools, resource/asset/native closure, signing mode and output stage digests. Extend existing qualification to distinct workspace roots and controlled timezone, mode, traversal and resource-order variation. Preserve boundaries between unsigned payload, aligned package and signed bytes. Reconcile candidate with current safeguards and supply the verified interface to P03-S02; do not narrow stable material after a failure.

**9. Acceptance:** Independently built positive packages match the promised byte boundary. Old packager, extra ZIP UID/GID metadata, wrong epoch, wrong signer and incompatible API floor fail intended diagnostics. Benign input mode/order/timezone variation normalizes as declared; changed resource/native bytes alter material identity. Interruption or failed copy cannot replace a previously verified APK, and mismatched receipt/APK pairs reject. Repeated receipt planning is deterministic while attempt metadata remains separate.

**10. Evidence limits:** Packaging equality is not compiler reproducibility, signer update installation, physical rendering or managed-runtime acceptance. API21 consumers cannot be silently moved to API24 to pass this mode.

**11. Completion and continuation:** Deliver implemented receipt/qualification changes, exact valid/bad/benign receipts and released schema/material artifact to P03-S02/P04; update14 and retained candidate. Return only a real signing/API contract contradiction to STAR.

**12. Authority:** Focused source implementation and disposable test packaging with existing test credentials; no key creation, signer substitution, merge, release, installation, closure or activation.
