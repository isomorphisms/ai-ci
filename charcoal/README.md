# Charcoal acceptance

The native presentation observer requires exact #212121 root/status/navigation
colors, light system-bar icons and #2F2F2F or #383838 control surfaces. It then
samples the actual compositor, preserving the existing independent tint mutant.
FastChat's palette-only entry checks both Android night-mode settings without
editing a provider, sending a request or changing a conversation. Archive
reopening is checked once in each system mode.

`check-frame.grease` uses FFmpeg's decoded frame to reject an application screen
with less than 80 percent dark pixels (luma below 80). This is a coarse guard
against a white root/window, not proof of text contrast, content, responsiveness
or absence of every light subview. A blank dark frame alone can pass; pair it
with functional and compositor checks. Use an explicit application-owned crop
when external content occupies the screen; never classify a user's light
document or photograph as a failure. No global pixel inversion is used.

`self-test.grease` provides an actual charcoal image and a white-background
negative. Consumers keep exact signed artifact identity and screenshot names;
physical MIRO C67 acceptance remains separate from hosted x86_64 emulators.

Historical FastChat and IB signed-input lanes retain the pre-charcoal observer
paired with those immutable historical APKs. They do not qualify the charcoal theme.
`charcoal-fastchat.yml` and the current producer branches use the new observer;
they require the fixed palette and reject deliberate live palette mutations.
The signed archive lane now requalifies the current charcoal source and retains
its exact archive digest and native source identity on both API29 and API34.

`charcoal-pasteboard.yml` samples the same signed Pasteboard and Chord Changes
candidates on API29 and API34 with system night mode off/on. Its fresh scene checks
the resumed native Activity, coarse frame darkness and independent #212121
root / #2F2F2F card pixel positions within the compositor's two-value tolerance.
This complements the producer's real clipboard, migration and card interaction
suite; it does not repeat that suite or establish rotation/transition coverage.
Chord Changes uses its actual typed Activity and fresh framework-control
hierarchy, with a #383838 button sample. The original seven-argument sampler
entry remains Pasteboard; the optional profile selects the documented app.

`charcoal-instruments.yml` checks unchanged signed Accelerometer, Spirit Level,
Gyroscope, Magnetometer, Ambient Light and Proximity candidates in both system
night settings on API29/API34. It verifies candidate digests/signers, fresh
namespaces, actual resumed Activities, a charcoal root pixel and light ink
inside the application canvas, excluding system-bar icons. This rejects a blank
launch window without pretending to read sensor values or establish accuracy.

The shared bootstrap stages the published portable `bin/grease` launcher with
SHA256 `37088097c36a2f82cf45aaea9392e4a4cf16155fecb9da87d08a9c7fb4d92e4a`
beside the unchanged qualified host engine. Consumer checks invoke that canonical
entrypoint; the underlying engine name remains package material. GitHub's fixed
composite-step interpreter is used only for these fixed bootstrap commands.
The canonical entrypoint locally passes frame positive/white rejection,
native/XML token mutations and the exact integer Idriç contrast replay.
