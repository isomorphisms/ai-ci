# Independent presentation checks

`prepare.grease` compiles the actual IB retained-source adapter against an
independent expected history. Host execution covers source order, generations,
revision refusal, cursor preservation, corrupt/incomplete input, range bounds
and incompatible history versions. A separately compiled guard-bypass producer
mutation must fail the stale-revision assertion. Both producers emit real DEX.

`observe-art.grease` runs external reflection and semantic observers against
those source-generated bytes on an existing API 29/34/35 emulator. It rejects
both the revision-bypass producer and the incompatible callback-signature DEX.
This proves those boundaries; it does not prove a visible UI, callback dispatch,
frame timing, keyboard behavior, an imported archive, or physical acceptance.

The consumers keep their existing independent reader acceptance pinned
separately. These checks do not replace or weaken it.

`ArchiveAcceptance.c` calls the actual ChatGPTExporter read-only native archive
adapter. It requires all ordered messages, exact roles including unknown,
content boundaries, decoded bytes, bounded text output, provenance and explicit
unsupported content. It rejects corrupt archive data and a separately compiled
assistant-to-user role mutation. Its supplied capture corpus is synthetic,
not a user archive or live-account observation.

`observe-ib-ui.grease` is a separate installed-application observer. After the
existing reader has produced actual retained data, it opens that application,
uses real History/Reader buttons, and checks the same reader View, projected
text, selection and scroll position. It selects the first retained source,
then independently reads the durable index, verifies its checksum, exact
source/generation and cursor, and requires the ordered history to be unchanged.
It only runs on an explicitly identified x86_64 emulator. Its Smali observers
are external test code, not product application sources; assembly alone is not
an Android execution receipt. It does not establish physical touch, recovery of
a live site session, a complete task timeline, or performance.
