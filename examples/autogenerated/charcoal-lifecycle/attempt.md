# Native lifecycle replay

Purpose: replay exact, already built and signed priority applications through
cold launch, a rotation request and return, background/resume and force-stop
reopening under both system night settings. Inputs bind the actual APK hash,
package, launcher, signer, source and producing run. The disposable runtime must
identify as an x86_64 Android emulator; existing namespaces are refused.

This is bounded process/file/Android-command orchestration through canonical
Grease. Native fork/wait was executed successfully before choosing it for the
screenrecord child. No generated program or candidate UI is substituted. Integer
orientation and pixel expectations remain independent of the application tokens.

The actual resumed Activity, charcoal edge pixel, nonblank light ink inside the
app canvas and portrait/landscape compositor dimensions are checked. Pasteboard's
declared portrait lock is preserved: it must stay portrait after the rotation
request. Each candidate is installed then replaced without uninstalling. Ten live
PNG frames and two real startup videos are retained per app/API. Video decoding
is required; proving every application-owned startup frame avoids white flashes
still requires sequence/ownership review, not an inferred PASS from settled PNGs.

This supplements earlier semantic suites. It does not assert preservation of a
particular scroll selection, dialogue-state coverage, sensor accuracy, imported
content color, ARM execution or physical C67 acceptance. External launcher/keyboard
frames in startup videos are not application-owned backgrounds. The Exporter
x86_64 package is its existing production-reader fixture with the same native
presentation source; its ARM64 development package stays separately identified.
