# Native network, history and selection fixture

This extends the existing independent SDK observer. Its candidate remains the
maintained checked IB Activity. The existing ai-ci ingestion fixture_server.c
serves a separate declared corpus through its existing routes, compiled by the
qualified ICK host toolchain. The /valid response links relatively to malformed;
the inherited /malformed route serves the second well-formed reader document
for this corpus. Endpoint naming is not an HTML parsing result.

The first HTML has a title, heading, relative link, café, a supplementary globe,
a soft hyphen, and twenty separately sourced paragraphs. Literal semantic
clipboard expectations preserve block separators and the original soft hyphen.
The second HTML has its own title and body. The original fixture files and
independently read Arena digests must match.

The external VisibleLinkPoint Runnable reads the actual SDK TextView and Layout
on Android's UI thread, finds a visible Next glyph point, and bounds it within
the SDK's visible rectangle. UiAutomation injects touchscreen down/up events.
The native event adapter and checked navigation then own acquisition. SDK
buttons exercise Back/Forward and the visible reflow selector; native copy must
replace a public stale-clipboard sentinel with exact source text and its source
label. The stock ScrollView receives a scroll action. A separate phase requires
Shizuku to be absent and traverses all three retained documents, including the
earlier public Example document.

Type sketch: the observer holds an Android Activity reference and measured
visible point, never an Idriç heap value or a source capability. Expected
fixture strings and history occurrence order are independent literals. Grease
will supervise the existing host fixture executable and actual instrumentation,
then invoke independent source/index checks. This does not grant transport or
admission authority to an observation or fixture.

These new network phases are source-only and NOT_RUN until their explicit
coordinator executes against an exact APK. Compiled decoder/selection/history
controls remain required. Emulator accessibility scroll and clipboard actions
do not establish physical drag gestures, tablet access or SEARCH acceptance.
