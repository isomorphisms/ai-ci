# Actual HTTP response observation

## Intended behavior and values

The admin observer must distinguish an HTTP failure of the main document from
a failed subresource. The IB companion adds the platform HTTP callback; this
change supplies independent installed acceptance through the existing observer.
It runs after the existing retention and replacement-installation journey.

The bounded domain has two controls: a main document returning HTTP 503, and a
document returning HTTP 200 whose stylesheet returns HTTP 404. A phase produces
an observed host PID, fixed completion result and numeric native diagnostics.
The fixture supplies three independent completed-response-write counters.

The oracle consumes a closed numeric log, the two distinct host PIDs and three
counter snapshots. It returns success only when the selected main-frame error
is observed, the subresource phase completes its document without a main-frame
error, and the counters show exactly the selected response progression.

## Laws and failure behavior

Known document attribution requires a preceding start under the same host,
Activity and renderer generations. An unknown error retains document epoch 0
and elapsed time -1; it cannot gain a timing claim from a later start. Invalid
keys, extra private exports, wrong hosts, wrong response codes, missing server
responses and out-of-order known events are refused. The existing public
classifier still classifies positive HTTP errors as site failures.

No response body, header, reason phrase or URL is added to numeric diagnostics.
The existing parent-byte metric excludes these diagnostic responses as well
as delayed child responses; it remains a scoped counter rather than total
network transfer. A completed error page is not evidence of authorization or
a useful admin action.

## Implementation boundary

This extends the maintained Grease coordinator and oracle and its existing
test-only Smali platform adapter. The observer invokes IB's real native Open
control and waits for the selected document to finish. It does not inject the
HTTP callback. The product's checked Idriç task model is unchanged. No new
Idriç compiler limitation or alternate implementation is claimed.
