# Independent Yente conversation process acceptance

## Types and boundary

Inputs are absolute paths to a compiled candidate executable and its material
directory. The output is a sequence of named checks and a final acceptance
verdict. The checker owns fictional command sequences and expected process
observations; it does not import Shallow's types, state transitions, or tests.

Central operations are `capture : List Text → IO (Int, Text)`,
`run_case : Text → Text → IO Text`, and a fail-closed exact observation check.
Effects are creating isolated temporary directories, writing TSV commands,
launching the actual candidate through `Escaped.popen`, checking exit status,
and reading output files. Temporary fictional state is not a secure vault.

Required invariants include audience separation, correction dependency
invalidation, exact-recipient/revision disclosure, preservation of distinct
account kinds and dates, and identical model requests when histories differ
only by information unavailable to that recipient. Malformed input and stale
model responses must be rejected without successful delivery.

## Implementation and verification

Source: `Accept.idric`, using the canonical Idriç compiler and Chez runtime
already used by adjacent independent process checkers. No generated-C,
Python, Node, or alternate application backend is an implementation fallback.

Host compilation passes using canonical Idriç source
`2bce7677f513d711875e978bd6f5ad28b9e54d58`, with `--source-dir
examples/autogenerated/yente-conversation -o yente-accept
examples/autogenerated/yente-conversation/Accept.idric`, `IDRIS2_CG=chez`,
and explicit `IDRIS2_PATH`, `IDRIS2_DATA`, `IDRIS2_LIBS`, and `CHEZ` values
from the verified compiler installation. Both executable wrapper and compiled
Chez artifact were observed. An initial totality diagnostic for `readFile`
was resolved by explicitly marking that IO operation `covering`, matching
the inherited process boundary rather than weakening a domain invariant.

Negative control: supplying `/usr/bin/true` as the candidate exits 1 at
`novel people and retained report identity`; a successful no-op process does
not satisfy the independently expected observation. The FP pipeline also
stops at its first stage when supplied `/usr/bin/false`, retaining exit 1 and
running no acceptance stage. Those observations qualify checker/runner refusal
only.

The final host run against the compiled Shallow candidate passes all 97 named
observations and emits `YENTE_AICI_ACCEPTANCE_OK`. This count includes process
and request-construction checks; it is not a count of independent semantic
properties. The four-stage Flexible Pipes execution also passes: fictional
conversation, permitted request construction, recorded response admission,
then this independent process oracle. Its demonstration stdout contains no
error receipts. The response is explicitly assistant-authored fiction and
model inference is `NOT_RUN`.

Mutation review exposed a flaw in the initial correction fixture: all three
hypotheses cited the corrected source directly, so shallow root-only withdrawal
could pass. The corrected fixture gives child and grandchild separate,
still-current evidence while making them depend on the root and child. Only
actual transitive invalidation removes them; independent support remains.
Later runtime tests use frozen artifact directories to avoid overwriting a
Chez artifact while another acceptance process executes it. An interrupted
concurrent-build run is invalid evidence, not a rejected semantic mutant.

Live model inference and semantic transcript quality remain separate from
this deterministic process oracle. The checker cannot turn a synthetic reply
or a shaped response record into evidence of language understanding.

## Language work

No new language requirement is established by this sketch. If compiling or
executing the real subprocess/file boundary fails, retain the minimal failing
Idriç source and first specific diagnostic before considering any fallback.
