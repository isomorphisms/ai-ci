# Independent Fixed Pasteboard qualification

`prepare.grease` builds the checked Idriç oracle and independent NativeActivity
copy fixture. The fixture performs SDK clipboard effects only in response to
visible input; it cannot call the consumer model or history provider.
`observe-art.grease` executes the exact reducer DEX extracted from the candidate
APK and compares every result with explicit independently authored expectations.
It must reject the separately source-compiled wrong-order mutant at case 2.

`observe-installed.grease` is an emulator-only acceptance procedure. It verifies
the emulator and shell identity before changing display geometry, starting the
official pinned Shizuku server, or inspecting private synthetic fixture history.
The decisive A/B/C check reads durable history while the copy fixture remains
focused, then checks it again after Pasteboard resumes. Permission decisions use
the real Shizuku dialog and confirm that it names Pasteboard.

The process-death control schedules a framework crash of the verified app PID,
requires its actual disappearance and matching AndroidRuntime crash receipt,
then compares exact history after restart. It does not substitute force-stop
for ordinary process death. Background am kill is insufficient for a live
provider process. AOSP ActivityManagerShellCommand runCrash definitions are
pinned to Android 10 blob `8f16ed4768deed6ecf407063ce3f94cf0220cd09`, Android 14
`569f55f7890fa51a4a7dea37f6188a9be4f4892b` and Android 15
`bbd432340e8f559d513da79207d8de92fa0020aa`.
No clipboard polling or accessibility content extraction is used by the candidate.

The oracle checks checksums, strict UTF-8, framed snapshots, unique identities
and contents, visible capacity and exact expected text/order independently of
consumer code. Bad checksums, malformed framing, invalid UTF-8, duplicate records
and the compiled semantic mutant have distinct refusal controls. Fixture text
includes indentation, CR/LF, code fences, supplementary Unicode and more than
8192 bytes. Only synthetic fixture history may enter these evidence artifacts.
The host oracle runtime is retained in an inner tar archive to preserve its
executable modes across GitHub artifact download. Every Android stage checks
the actual APK against the producer receipt and retains the consumer, frontend,
backend, ICK and NDK identities alongside its result and device fingerprint.

`prepare-guards.grease` builds an independent smali instrumentation controller
and three deliberate source mutants: an exposed provider, a disabled native
UID guard and a disabled private-credential comparison. The UID control uses a valid private capability inside the
verified emulator and a real unprivileged application caller. Its token never
enters a shell argument, log, result or artifact. It sends no history event.
The exposed-provider control also disables the reinforcing native manifest
permission check and recompiles the actual native source, isolating Android's
permission gate from application startup validation.
The credential control uses the real shell UID and a fixed invalid credential
which cannot equal the private hex key. It requires explicit provider refusal
without changing history; the comparison-bypass mutant must expose acceptance
while retaining the other authorization checks.
`observe-controls.grease` requires distinct targeted failures for all three mutants,
then restores the exact positive APK before exercising companion crash,
reconnection, real manager revocation/regrant, framework expiration and reboot.
The fixture now confirms the actual clipboard value after every test copy;
it logs only fixture indices and metadata, never text or origin identities.

`observe-ui.grease` exercises actual tap-to-copy, card and header swipes, all
three boards, visible protection/deletion, current/recovery deletion, numbered
overflow, all-protected boards and archive restore/clear controls.
`observe-migration.grease` begins with an absent package on a verified fresh
emulator, populates the actual retained version-2 APK through real copies,
upgrades it without changing UID, and independently inspects the migrated data.
Its corrupt-record control and subsequent resets use only that synthetic test
namespace. These reset commands are never physical-device procedures.

The original ART attempt failed case 21 because text-file output truncated the
NUL fixture. Fixture generation and expected-text input now use explicit binary
UTF-8, with a NUL write/read control. The candidate's refusal assertion remains
unchanged; no backend workaround or expected-result weakening was introduced.
