## Boundaries and independent probes

`run.sh` requires the exact checkout plus `AICI_C_COMPILER` and `AICI_ICK_REVISION`; it has no generic compiler fallback. It fails on changed mutation anchors, any unavailable test, a surviving mutant, compile failure, wrong failure reason, absent output marker, or fewer than six records. The output includes case IDs, SUT + AICI + ICK revisions, candidate/compiler/executable digests, observed verdicts, oracle identity and fixed-case seed. The surrounding CI workflow preserves stdout for each candidate and the receipt.

The AICI oracle uses hand-evaluated coefficient/point pairs with powers 1–5, including complex coefficients and derivatives with respect to **u**. Holomorphic's reference uses binary64 complex powers and randomized seeds. They share the externally stated mathematical specification, not expected values derived from production internals.

**Still NOT VERIFIED:** full live shader q/phase/log-modulus semantics or decoded RGB; CPU sampling-domain relationship; rendered GLSL source actually executed in Android; MIRO A1 PowerVR; deployed Flexible Pipes mandatory dispatch; generic generator-output enforcement; Cockswain follower retirement. AICI C test is a *host CPU* witness only. All claims outside this boundary stay unresolved.

## Recovered test-generation provenance and alternative explanations

- The CPU search was introduced by `ded08c1ad784bc043ef9f55c268b13e92e196229` (2026-08-22), with the worker smoke added in `60e2ffc040269ee796f7debeedb2a41a69d89735` later the same day. Both belong to [Holomorphic PR #22, “Random holomorphic deformation with three workers”](https://github.com/isomorphismes/holomorphic/pull/22), whose scope explicitly described the disturbance metric as **a first heuristic, not a canonical mathematical definition**.
- **Competing explanation A:** test generation optimized for easy green proxies and silently treated worker startup as mathematical correctness. **Competing explanation B:** this was deliberately a narrow smoke test for a first heuristic, and *later acceptance wrongly generalized its claim*. The original title, separation into a later commit, and the PR scope are evidence for B; no retrieved agent prompt or generator transcript establishes A. A test's inability to certify a property it never claimed is not by itself proof its author intended it to.
- The verified defect is that **five mathematically wrong evaluator variants are accepted by the original worker smoke**, so that smoke cannot be promoted to polynomial semantic acceptance. No historical production semantic bug was identified merely by synthesizing those five mutants. Stronger root-cause classification stays open pending trace of what generated the acceptance requirement and who promoted which test result.
- The AICI repair supplies an independently executed six-value hand oracle, preserved wrong and correct compiled candidates/logs, and a receipt gate that rejects omissions, malformed results and changed source/test/target identities. The receipt checker only verifies evidence structure and local consistency; without an independent runner it would be forgeable and cannot substitute for behavioral truth.

## Root-cause hypothesis, not a finding

`requirements → generated implementation → generated tests` may favor cheap startup/finite/source-string assertions. The reproduced Holomorphic smoke shows that such assertions do not distinguish five semantic errors. It does **not** identify the exact prompt, agent, template or selection mechanism responsible. The proposed upstream repair is to require machine-recorded invalid controls for each material semantic claim and to make promotion fail on missing, skipped, incorrect-target or surviving-mutant evidence. That generic enforcement remains incomplete and belongs to AICI #183 and FP #69.
