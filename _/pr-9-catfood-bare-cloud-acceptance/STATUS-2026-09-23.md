# Status on 2026-09-23

The core idea of PR #9 is still useful, but the implementation is stale relative to both repositories.

Current ai-ci `main` does not contain this Cat Food acceptance directory or workflow. Meanwhile current Cat Food has evolved well beyond the August shape assumed by this branch: it now has explicit cloud/container and Android-runtime boundaries, Idric-Net in the host build graph, broader stable command exposure, package/follower evidence, and more explicit provenance concepts.

A reconstruction should therefore preserve the **acceptance principles**, not blindly restore the old paths.

Questions to resolve in current architecture:

- whether the clean-machine gate should target Cat Food's current `container`, `cloud`, or both contracts explicitly;
- which current host tools belong in the required acceptance set, including Idric-Net where appropriate;
- which assertions should inspect Cat Food provenance/receipts and which should use only stable public commands;
- how to prove an artifact came from Cat Food without coupling every behavioral fixture to private paths such as `/opt/Idric/build/exec/idris2`;
- which exact-output fixtures remain representative of today's language/tool interfaces;
- how to retain the no-hidden-rebuild rule;
- how to retain deterministic loopback testing for ICU;
- how the daily drift run should interact with ai-ci's newer evidence and merge-verdict architecture.

The old branch should not be reopened as production code. A follow-up issue owns reconstruction against current `main`; this archive supplies the exact historical implementation and rationale.
