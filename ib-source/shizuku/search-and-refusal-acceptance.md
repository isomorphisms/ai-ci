# Installed SEARCH caller and HTTP refusal controls

Navigation reader-v2 is an explicit extension of the frozen eight-argument
navigation profile. It requires real ICU HTTP404 acquisition after Reader Two,
visible exact status, unchanged native history, retained title and exact source
clipboard. The same installed reader then receives a no-result SEARCH with a
spoofed referrer, an actual IB-origin for-result SEARCH and a real SINGLE_TOP
warm intent. Each must display its exact refusal, preserve the last-good title
and leave the independently checked three-document journal intact.

External SDK instrumentation captures the actual framework-created Activity;
it does not call a fake receiver or assign a caller identity. A fresh real
ChordReader UI phase is separately available: Android SEND opens the public
query fixture in the maintained ChordReader import form, and its actual
search-web button dispatches the candidate native for-result code. The observer
requires Android getCallingPackage=org.isomorphisms.chordreader.dev and the
literal once-encoded Google URL in the actual IB input widget. That phase
qualifies handoff/encoding only. Google status, static content, consent or bot
challenge must be recorded separately, never promoted to a successful search.

Smali builds only these SDK observers. SearchDispatch exercises the real
Activity manager on the UI thread; ReaderAddressSnapshot reads the actual
TextView on that thread. No candidate DEX, network transport or reader logic
is supplied by the observer. Exact-head execution of the new profile is pending.
