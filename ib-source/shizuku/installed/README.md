# Installed native Shizuku client acceptance

This independent instrumentation runs against the installed checked IB Activity
and its native platform adapter. Candidate classes remain compiler-generated;
the small observer alone is assembled from smali. It verifies an actual emulator,
the declared API/ABI, official Shizuku release bytes and signer, then installs
without uninstalling or clearing data. The same UID and signed APK byte readback
are required after every replacement.

The official Shizuku server owns real Binder delivery, attachment, permission UI
and permission queries. The observer clicks the checked Activity's native
controls, denies and grants through the real manager, stops that isolated
emulator server and checks revocation and reconnection. An unrelated application
UID must fail Android's provider permission guard. A separate well-formed fake
peer is used only to reject an ordinary app's delivery attempt before the server
starts. It is never counted as Shizuku authorization. Compiled UID-bypass and
death-no-op candidates must fail their specific independent expectations. The
strict-flags candidate restores the historical one-way transport refusal and
must fail the real attachment expectation before the repaired candidate passes.

The fixed kill command is confined to a fresh, independently identified emulator.
The SDK-only mode does not launch Grease/ICU or claim document behavior. The
explicit `reader` mode is mandatory for the complete worker producer schema.
It enters `https://example.com/` in the native UI, waits for independently
expected document text and an acknowledged source, then reopens with Shizuku
stopped, after replacement installation and after emulator reboot. It records
an actual view screenshot before instrumentation terminates. Its host observer
then obtains root solely to copy the committed private Arena for the existing
independent source oracle. Candidate transactions still run with the real app
and shell UIDs. A changed committed byte must fail the independent readback.
Root is restored to shell before continuing. This mode is unqualified until its
exact candidate executes successfully; no fixture or SDK pass implies it ran.

Neither mode establishes physical TAB_P10 acceptance, clickable link/history,
source-faithful selection or SEARCH behavior.
Synchronous SDK RPC timeout behavior also requires further qualification.
